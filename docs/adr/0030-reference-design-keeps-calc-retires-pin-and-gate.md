# ADR 0030: NutriBuddy 参考设计只保留算术层，退役 pin 与 gate

## 状态

**已采纳 (Accepted)** — 2026-09-20

- **部分取代 ADR 0026**：只取代它的参考设计组件集（0026 列的是 Deterministic Gates +
  Sandboxed Calculator）；0026 的其余结论不变。
- **Related**: ADR 0025（published ReAct 用全量 context），ADR 0028（基建 void 不入分母），ADR 0027（harness 世代）
- **依据**: `reports/ablation-buddy-rerun-20260920.md`（修正步数预算后的重跑与全部配对数据）

## 背景

2026-09-19 的 buddy 消融本意是证明"认知脚手架对复杂营养任务有价值"（ADR 0026 的阶梯：Vanilla 60% → +Gates 75% → +Calculator 88.5%）。修正它的步数预算缺陷后重跑，`buddy-calc` 的配对结果从 5 FAIL→PASS / 0 PASS→FAIL（p = 0.0625）变成 3 / 2（p = 1.0）：效果没有复现，基线自己在两次运行间就移动了 5 / 2。

进一步按机制核对，三个层的处境完全不同：

1. **`gate`（`check`）没有任何可防的暴露。** 扫过仓库里 93 个带逐任务标签的运行：**含过敏原的计划到达 env 的次数 = 0**，被判 `allergy` 标签的任务 = 0。也就是说它的安全半边从未触发过一次——不是"效果小"，是没有机会。它的另一半（拦截违窗计划）在 12 步那版里触发 4 次 / 20 个可比任务，ITT 4 / 1、p = 0.375，且 4 个"收益"里 3 个 `regen_fired = 0`（机制没触发，就是噪声）。另外它的窗口是从观测推导的，Oracle 的窗口是权威值：两者不一致时会**拒绝一个本来会被判过的计划**；对 evaluate 型提交（`verdict` + `items`，且要精确匹配 Oracle 的候选）尤其致命，那里被弹一次就可能偏离唯一答案。
2. **`pin` 的失败模式已经被移除。** 它的机制是"约束在上下文被截断时仍然存活"。ADR 0025 已规定 published ReAct 用全量 context，`--context-limit 12` 只是消融；本仓库随后把全量 context 变成代码默认（`995e698`）。全量 context 下不存在"约束被滑窗挤掉"这个失败模式。它唯一一次测量（2026-09-18、`mini-fast`、9 题）是 7/8 = 87.5%（剔除 infra void）对基线 8/9 = 88.9%，而该 split 自己的 README 写明它无法测量 harness。
3. **`calc` 保留位置，但效果仍未被证明。** 它的目标失败模式（窗口算术）在**弱模型**身上是主导失败：当前 63 题考卷上 `window` 占 kimi-k3 失败的 16/31、minimax-m3 的 25/44、doubao-lite 的 18/47，而 GLM-5.3 在当前 harness 世代（streaming react，53/63）上只有 2 个（旧世代那次 38/63 是 5 个）。消融恰恰挑了最不需要它的模型——而 ADR 0026 阶梯里那句 88.5% 本身就出自弱模型（DeepSeek-V4-Flash × 10 题 v2.3，且当年的 `buddy-check` 把 calc 与 gate 一起开），换到 GLM-5.3 复现不出来，这与"能力补偿价值是模型条件性的"一致。它目前唯一的正面证据在成本轴：mini-harness 修正预算配对中，同通过率下步数 12.41 → 10.68（-14%，14 题更少 / 2 题更多，符号检验 p = 0.0042），墙钟 -31%；但 token 成本未被记账，而 sheet 每步约 +264 tokens，在全量 context 下会被反复重发（11 步约 +17k tokens/任务，参考 ~40k/任务），所以"省步数"未必"省 token"。

## 决定

1. **参考设计（对外主张、产品叙事、后续实验的默认配置）只包含算术层 `calc`**，且只在其机制有空间的地方（弱模型 × 窗口失败任务）主张有效性。
2. **`pin` 与 `check`（gate）退役**：不出现在消融矩阵里，不作为参考设计的组件，任何报告不得把它们计入 NutriBuddy 的价值主张。
3. **代码保留、主张撤销。** 这些 scaffold 仍留在 `SCAFFOLDS` 中作为实验与控制代码（`resample` 是"多花一次 completion"的非语义对照，仍需要它）。保留代码不等于保留结论。（2026-09-21：策略轴的旧名 `arm` 与 `ARM_FLAGS` 已改名为 `scaffold` 与 `SCAFFOLDS`，值也去掉了 `buddy-` 前缀；本 ADR 的结论与数字未变。）
4. **buddy 消融暂停（parked）**，直到有一个能判定的设计：按失败模式选样本（不是加重复）、读条件指标（窗口标签失败数、到达 env 的违规次数、tokens/pass），而不是混合 split 的通过率。
5. **成本主张必须用 `tokens / pass`**，并在 harness 里接上 usage 记账（现在 `ReActHarness` 丢弃 usage）。步数只能作为辅助证据。

## 后果

- 论文/对外叙事里不能再写 "+Gates 75%" 这类阶梯数字：gate 的价值既不成立，也从未有机会成立。若将来某个模型/prompt 组合真的产出到达 env 的危险计划，那是一次**新的测量**，而不是复活这个 scaffold。
- 若有一天重新启用截断 context 的跑法，`pin` 只作为那个跑法的一部分回来，不作为默认组件。
- `calc` 的下一步是**弱模型上的配对运行 + token 记账**，判据预先登记（同 pass ±1 题时 tokens/pass 下降 ≥ X%，或 tokens/pass 不升而 pass 提升 ≥ Y 题）；在此之前，任何"脚手架有用"的表述都只能写成"未证明"。
