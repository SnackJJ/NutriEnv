# ADR 0023: 双层评测协议、物理白名单容差与交互幂等性标准

## 状态
**已采纳 (Accepted)** — 2026-08-30

## 背景与核心诉求
随着 ADR 0019/0020/0021/0022 的实施，NutriEnv 题库流水线已具备 75:25 食物分层抽样、去标签化餐桌大白话生成与三独立厂商大模型常识投票（DeepSeek + Kimi + GLM）能力。在工程演进与终审复核中，关于**基准评测的公平性、题目可解性与真实人机交互复杂性**，提炼出了四个深层次架构问题：

1. **题目可解性（Soundness）与考试区分度（Hardness）的悖论**：如果给受测 Agent 详细的手册指引，担心考试太水没有区分度；如果完全不给指引，又担心无法验证题目本身是否物理上 100% 绝对可解。
2. **Oracle 确定值 vs 物理克数容差（Tolerance Range）**：真实餐桌上一盘菜、一碗饭存在 $\pm 10\%\sim 15\%$ 的合理物理波动。若 Oracle 死锁为一个单一数值，会将做出合理常识推断的优秀 Agent 误判为 0 分。
3. **交互幂等性与真实对话习惯（Idempotent Updates）**：用户反复提醒既有过敏原（如 *"Remember I'm allergic to peanuts"*）是真实世界高频出现的行为，评测体系必须能够包容并正确评价这种幂等确认。
4. **规则库维护成本 vs 大模型常识推理**：写死正则与量词字典（`resolve_portion`）具有天然的无穷边界死角，大模型常识投票（LLM Vote）配合物理白名单门禁才是唯一具备可扩展性的现代方案。

---

## 核心架构决策

### 1. 双层评测协议架构（Dual-Spec Benchmark Protocol）
我们将评测体系在架构上清晰解耦为两个独立阶段：

```
[流水线候选生成]
       │
       ▼
┌─────────────────────────────────────────────────────────────┐
│ 阶段一：题目通过性与无矛盾验证 (Soundness Verification)       │
│                                                             │
│ • 工具：配备【完整接地手册与排障规则】的 Oracle Solver Agent    │
│ • 目标：必须对全量题目跑出 100% Pass (check_achievable)       │
│ • 意义：数学上证明本套考题 100% 物理可解，零幽灵食物，零逻辑死锁 │
└─────────────────────────────────────────────────────────────┘
       │ (100% 验证通过后冻结为 Gold Split)
       ▼
┌─────────────────────────────────────────────────────────────┐
│ 阶段二：正式 Agent Benchmark 盲测 (Model Leaderboard)       │
│                                                             │
│ • 工具：受测候选大模型（GPT-4o, Claude 3.5, DeepSeek, Qwen）  │
│ • 手册：仅提供【react.py 标准工具定义与简明交互协议】          │
│ • 考核：纯粹检验 Agent 的真实口语常识推理、工具搜索与物理接地能力 │
└─────────────────────────────────────────────────────────────┘
```

* **阶段一（通过性证明）**：使用具备领域完整先验的 Baseline Solver 跑通 Round-Trip（`Scorer.score() -> 100% Pass`），证明题目本身健康可解；
* **阶段二（能力盲测）**：向被测模型隐藏小抄字典，以权威统一的极简手册进行公平盲测，测出模型的真实能力梯队。

---

### 2. 黄金锚点与物理白名单离散容差（Gold Anchor & Portion Tolerance）
* **Oracle 黄金锚点**：每个食物在 Oracle 中保留一个由三模型投票及人工核准确立的权威 Gold 克数（如 `190.0g`）。
* **Scorer 离散容差机制**：
  * 当 Agent 预测的克数落在 **$[0.85 \times \text{Gold}, 1.15 \times \text{Gold}]$** 区间内，**且**该克数属于 FNDDS 物理数据库中合法登记的离散档位（`matches_portion_table(food_id, grams) == True`）时，判分器判定该项物理接地为 **Pass**；
  * 彻底杜绝因“选了 180g 的 cup 还是 190g 的 qns”而惩罚正确 Agent 的假阴性（False Negative）现象。

---

### 3. 交互幂等性与重复确认规范（Idempotent Update Invariant）
* 用户重复声明既有属性（如用户已对花生过敏，再次要求 *"Add peanut to my allergies"*）属于受支持的真实人类交互，在 Split 中打标为 `situation: "idempotent_update"`；
* **预期行为**：Agent 应平稳识别并向用户确认既有状态（无需重新推导或报错），系统断言环境状态在操作后保持合规不变（`Profile == Oracle`）。

---

### 4. 大模型常识投票为主力与低共识保留候选机制（LLM Vote Primary & HITL Mark）
* 彻底确立 **DeepSeek + Kimi + GLM 三模型投票为主力接地引擎**，不再为无穷无尽的口语量词堆砌硬编码正则字典；
* **低共识投票处理原则**：
  * 当三模型投票出现完全分裂（如 1/3 或共识率 $< 66\%$）时，系统**保留 3 家模型的推导建议与理由**，标记 `needs_human_review=True` 并收录于 `data/candidates/` 候选集；
  * 由人类审核员（HITL）进行最终仲裁打标，未获审核通过的低共识题绝不自动流入正式 Gold Split。

---

## 预期效果与收益
1. **消除出题者的死锁纠结**：通过阶段一的 100% Round-Trip 验证，完全确保考题无 Bug；通过阶段二的精简协议，完全确保 Benchmark 具备极高的区分度和对抗性。
2. **消灭判分假阴性**：物理白名单离散容差机制让合规的常识推导得到公正评价。
3. **人机对话全真拟态**：完美包容人类用户的确认、提醒与地道餐桌口语。
