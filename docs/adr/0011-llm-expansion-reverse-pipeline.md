# LLM 造题采用逆向采样管线：代码选材，LLM 只组装 query

LLM 扩写层（docs/llm-generated-exam-data.md §7 步骤 5）不采用"LLM 自由提案 (food, 表达)"，
改为**逆向采样**：确定性代码先从 FNDDS 锚点表随机采样 `(food_id, anchor_key[, quantity])`，
把素材（食物名、锚点表达、family 要求）放进 prompt，LLM 只负责把素材组装成一句自然语言
query；所有克数由 `resolve_portion` 从表值确定性计算，数字全程不经过 LLM。

原因：LLM 自由提案的食物/表达可能不存在于 FNDDS，克数锚点无法追溯（v0.5 的降级话术问题
正是"锚点没从表里来"造成的）；逆向采样把"LLM 产出永远是候选、克数锚点=表值"的铁律变成
结构约束而非事后检查。备选方案：LLM 自由提案（否决——锚点不可追溯）、LLM 只提案表达
（否决——仍给 LLM 选材机会），逆向采样（采纳）。

采样采用**超量取料 + LLM 组餐**：代码按需抽取超量的食物池（如 8 种 FNDDS 食物），LLM 从
池中组合出合理的一餐（如牛羊肉同餐、虾鸡不同餐）并写 query；每个组合内食物表达必须能被
代码反解回 PortionFact，反解失败即拒。组合本身产生多样性时保留多条候选；素材固定（单
食物或组合空间唯一）时择优一题。克数仍全部由代码从表值计算，LLM 不接触数字。
