6. 本轮机制与工程变更 (What Changed)

难度分层、可达性防线与物化脚本重构
1. evaluate 全面采用六个声明难度层表驱动
不再用单一形态填充配额，而是将 EVALUATE_ROWS 扩展为 55 行，显式划分为 6 个难度层（single、pair、triple、long、explicit_grams、synonym），使候选餐评估能力具有清晰的梯度覆盖。
2. 修复 peanut-butter / peanut-allergy 冲突并增加可达性门禁
排查发现有 4 道题因花生酱冲突导致不可通过：即使 agent 准确提交了题目要求的全部食物，Scorer 仍会因画像中既有的花生过敏原判定扣分。该问题在冻结前由可达性校验器（achievability check）及时捕获，已在物化器中完成修复，并写入 validator.py 作为强制门禁。
3. 修正时态语意不符题（吃完记录 vs 计划评估）
人工审查发现 1 道题的口语 query 包含“I already ate after the gym... submit that as the plan”——过去时态的进食属于 log 任务，导致该句子在语义上并未 entail 被打分的候选餐计划终态。已重写该 query 确保语义与终态严格一致。
4. 物化脚本重构为统一的参数化流程
物化器（materializer）已整合重构成单一参数化脚本。通过该脚本可将 v0.2 完全字节一致地重新生成出来，严格验证了本次重构未引入任何非预期变更或历史数据漂移。

7. 已知缺陷与遗留问题 (Known Gaps)

实事求是记录，不粉饰、不回避
1. recommend (41/72) 与 constrain (16/36) 成为剩余主要缺口
在 evaluate 达成满配后，剩下的 84 题缺口主要集中在 recommend（差 31 题）和 constrain（差 20 题），它们将是 v0.4 推进的核心攻坚对象。
2. evaluate 难度层实质为同一维度的多级呈现
single / pair / triple / long 四个层级本质上是同一个维度（列表提取负载 list-extraction load）的不同长度呈现，而 explicit_grams 实质是对照组而非更高难度。它们是诚实的测试槽位，但不应被夸大为四个独立的复杂能力。
3. 本轮 56 条新增题目未经人工逐条审核
新增的 56 项题目全部通过了机器门禁校验与 LLM 自动化复核，但尚未由人类专家逐题通读核验。在最终进入 v1 冻结集前，仍需执行全面的人工核准。
4. 存在已冻结的重复食物组合 (v0 与 v0.2)
v0-eval-snack-001 与 v02-eval-yogurt-banana 均为香蕉 + 希腊酸奶的组合。由于两道题在之前版本已分别冻结，为保持字节一致性，该重复项将留待后续主版本跃迁（version bump）时统一清理。
5. 40 题公开校准集是否计入 240 最终分仍未决
关于 v0-gold.json 中的 40 道公开校准题目是否计入 240 冻结测试集的最终报告分，目前尚未确定结论（涉及防泄漏与公开集定位），需后续专项 ADR 裁定。
