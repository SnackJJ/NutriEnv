# NutriEnv v2.2 假阴性审计与判分容错治理报告

## 一、 审计背景与核心目标
在基于权威 100 题基准 `v2.2-gold` 与 20 题验证集 `v2.2-mini` 开展真实大模型（DeepSeek-V4-Flash / DeepSeek-V4-Pro）实跑评测过程中，针对模型失败题目的完整交互 Trace 进行了逐行代码与状态机断言审计，重点排查并根治“**模型决策正确、但在评测端因格式死锁或题意欠规格化而误判**”的假阴性（False Negative）问题。

---

## 二、 假阴性定位与修复清单

### 1. 账本时间戳默认值容错 (`eaten_at: "now"`)
- **根因**：当用户 Query 未显式指定餐次（如 *"I had a hamburger and popcorn"*）时，模型按 ReAct 协议缺省省略 `eaten_at`，环境默认打标为 `"now"`；而 Oracle 预设为 `"today-lunch"`。判分器原先强制 `got.eaten_at == exp.eaten_at` 导致克数与食物完全正确的操作被误判为 `log_miss`。
- **修复**：在 `Scorer._ledger_row_matches` 中支持缺省时间槽兼容（`got.eaten_at == "now"` 或 `exp.eaten_at == "now"` 视为兼容）。

### 2. 评估核准解释文本容错 (`verdict: "accept"` 附带理由)
- **根因**：模型在核准餐单时（如 `adr24-comp-8309`），倾向于在 `reasons` 中附带人类可读的自然语言解释（如 `["No allergy, snack fits windows"]`）。底层协议原先抛出 `ActionError` 导致动作被拒绝。
- **修复**：在 ReAct Harness 适配层自动清洗 `accept` 状态下的多余文本，`Scorer` 仅在 `reject` 状态下校验违规 Reason Codes。

### 3. 宏量拒绝理由的超集容错 (`gold_reasons.issubset(got_reasons)`)
- **根因**：对于极低卡路里餐品（如一片火腿配米饭），客观上同时存在卡路里不足（`kcal_lo`）、蛋白质不足（`protein_g_lo`）与脂肪不足（`fat_g_lo`）。原判分器强制要求集合严格全等（`got_reasons == gold_reasons`），模型精准指出多项不足反而被判 `wrong_goal`。
- **修复**：在 `Scorer._score_verdict` 中，只要模型识别出 Gold 判定的核心违规项（`gold_reasons.issubset(got_reasons)`），即判定为有效拦截。

### 4. 标签与原因代码别名规范化 (`normalize_tags` & `normalize_reasons`)
- **根因**：模型写入的 `'tree nut'`（带空格）与标准 `'tree_nut'` 未对齐；模型偶尔输出缩写 `'carb_lo'`、`'protein_lo'`。
- **修复**：`normalize_tags` 自动将空格/连字符转为下划线；`normalize_reasons` 内置常见缩写别名映射表。

### 5. 题目同义词与加工方式语义明确化
- **根因**：FNDDS 存在同品类不同油脂/配方细分（如黄油煎蛋 vs 植物黄油煎蛋、带炒面 vs 无炒面牛肉炒面、家常松饼 vs 商业松饼），Prompt 缺少限定词导致模型无法预测特定 Oracle 绑定项。
- **修复**：在 `v2.2-gold.json` 与 `v2.2-mini.json` 中补全明确限定词（`"homemade cornbread muffin"`, `"reduced-sodium cooked mixed vegetables"`, `"ready-to-eat flavored popcorn"`, `"beef chow mein without noodles"` 等）。
