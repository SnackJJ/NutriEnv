# v1.0 Candidate Pipeline 路线图

> 配套：`docs/llm-generated-exam-data.md`（方案）、`docs/adr/0011`（逆向采样）、
> `docs/adr/0012`（复合题）。本报告是实施权威：阶段、验收、冻结边界。

## 目标

用 LLM 扩写流水线（Candidate Pipeline）生产 v1.0 全新考试：锚定完整 FNDDS
PortionFact 的真实用户话术，替代 v0.5 的降级话术（g/cup/slice 为主、0 条
serving/thick/fl_oz）。v0.5 归档为回归基线。

## 冻结边界（全程不可违反）

- 判分：`Pass ⇔ end state == Oracle` 一字不动；复合题 = 每个 sub-oracle 都匹配。
- 克数：唯一来源是 FNDDS 表值（PortionFact）；LLM 不接触数字（结构约束，非事后检查）。
- 考试：v1.0 是冻结 JSON 文件（ADR 0006），不 live 生成。
- catalog：`catalog-v1.sqlite` 是**新文件**；`catalog.sqlite`（v0.5 的）字节不动。
- 手册对称（AGENTS.md 纪律 4）：任何进题表达先同步 `_SYSTEM_V1_TAIL`。
- 每个阶段独立可回滚到上一冻结版本。

## 管线（术语见 CONTEXT.md「Data generation」）

```
Sampler(代码) → Expander(LLM) → Resolver(代码, fail-closed) → Judge(LLM 小模型)
→ validate_draft(代码, D4 强制) → Review harness(LLM) → 人审(异常) → Freezer(代码)
```

- 保留规则：组合多样性 → 每池 ≤3 条；素材固定 → 择优 1 题；食物 id 多集哈希去重。
- Profile：代码按 persona 生成 S0（数值代码定），LLM 只润色人设文本；gym 混报
  克数 + PortionFact（轻健身 "a cup of milk + two eggs"，重健身才全克数）。

## 模型路由（百炼/DashScope，io/chat.py 已接）

| 环节 | 模型池 | 策略 |
|---|---|---|
| Expander 生成 | qwen3.8-2.4t-a95b / qwen3.8-max / deepseek-v4-pro-0813 / deepseek-v4-flash-0731 / glm-5.2 / kimi-k2.7-code | 跨题库轮换，同素材多模型各出候选，增多样性 |
| Judge | deepseek-v4-flash-0731 / qwen3.7-flash-2026-07-15 | 小模型，K=5 / threshold=0.6 / temp 0.7 / 512 不变 |
| Review harness | 多模型子代理 | 一致性/自然度/蕴含 + 汇总 |

每个模型 id 在 Phase 1 先 smoke 验证（DashScope 端点可用性、免费试用额度内）。

## 阶段与验收

### Phase 0 — 试点前代码缝（无行为变更，先落地）
- **D4**：`validate_evaluate` 的 query↔Row 反解改强制（查不到即拒，不静默跳过）+ 回归测试。
- **公开 `realize()` 缝**：`Generator._*_from_row` 抽为 `bench/realize.py` 公开接口；
  退役 `Generator.sample()`（`run_split --seed/--n` 分支移除）；`bench/generator.py` 归档。
- **归档/删除**：`scripts/ingest_usda.py`、`scripts/build_catalog_from_local.py`、
  `data/catalog-snapshot.json`（git 历史保留）；v0~v0.5 split 与 `test_v0{1..5}_split.py` 保留。
- 验收：pytest 全绿（移除 factory 测试后总数变化记录）；landing_verify PASS；冻结文件零 diff。

### Phase 1 — catalog-v1 完整重建（行为变更，走纪律 2）
- `scripts/fndds_dry_run.py` 对完整 FNDDS 策略重跑 dry-run，列"哪些食物克数会变"清单。
- codex 审 dry-run → 主 agent 裁决 → 构建 `catalog-v1.sqlite`（`build_fdc_catalog.py`
  的 `_portion_key` 按设计文档点 1 修正，保留 thick/thin/regular/oz/QNS）。
- `portion_table.py` 白名单对 catalog-v1 重算（表值集变化属预期）。
- 验收：v0.5 回归链（`catalog.sqlite` 不变）仍全绿；catalog-v1 键分布报告
  （25 → 数百种食物、qns 覆盖 ~99%）；不冻结任何 split 之前先过 dry-run 门。

### Phase 2 — Sampler / Expander / Resolver
- `bench/pipeline/sampler.py`：batch seed + 超量食物池（~8 种/池，按 family 约束），
  manifest 记 (seed, 规则版本, catalog sha)。
- `bench/pipeline/expander.py`：prompt 模板（素材 = 食物池 + persona + family 要求），
  多模型轮换；输出 = 组餐 + query（结构化 JSON：items[{food, expression}], query）。
- `bench/pipeline/resolver.py`：每个 expression 反解回 PortionFact（fail-closed）；
  包含性（食物名出现在 query）/泄漏/手册对称/近重哈希检查。
- 验收：合成样例表驱动测试；反解失败/泄漏/近重各故障注入测试。

### Phase 3 — Judge 换模型 + 灰区重验（纪律 3）
- judge 默认模型换 deepseek-v4-flash-0731（可注入 qwen3.7-flash-2026-07-15）。
- **灰区三对重跑**：sandwich 1.5× / lasagna 1.2× / omelet 2.0×，ground truth 已知，
  通过才封 gate；不通过则回退模型或裁决阈值（阈值变动须另开裁决）。
- 验收：灰区报告；`tests/test_grams_gate.py` 全绿。

### Phase 4 — Review harness（P2：试点即接入）
- `bench/pipeline/review_harness.py`：多模型子代理各出 (consistency/naturalness/entailment)
  评审 + 汇总（与 grams_gate 同款 judge 注入模式）。
- 验收：对合成候选输出结构化汇总；人审只处理标记异常的候选。

### Phase 5 — 试点 20 题全链跑
- 20 题 = 8 单食物 log（择优）+ 6 多食物 log 一餐（≤3 条/池）+ 6 evaluate 一餐；
  覆盖 qns/thick/thin/fl_oz/cup/slice 各 ≥1；persona everyday + gym（混报）。
- 全链：Sampler → Expander（多模型）→ Resolver → Judge → validate_draft → Review
  harness → 人审 → Freezer（`v1.0-gold.json` 绑定 catalog-v1 sha）。
- 验收：20 题全部过 gate + 人审；`load_exam` 指向 v1.0 跑通；`landing_verify` 改造
  后对新考试 PASS；每题 oracle 克数可追溯到 PortionFact；手册覆盖新增表达。
- 记录试点统计：素材→候选→通过率、人审负担、每模型产出质量。

### Phase 6 — 扩量 + 复合题
- 按试点统计定全量规模（目标 240 基础 + 复合题额外配额，ADR 0012）。
- 复合题形状（多 oracle 合同、判分、配额数字）单独设计 + 再裁决一次后实现。

## 风险登记

| 风险 | 缓解 |
|---|---|
| 百炼模型 id 不可用/额度 | Phase 1 smoke；备用 provider 回退（DeepSeek 直连） |
| judge 换模型后灰区不过 | 回退模型；阈值变动须另开裁决 |
| LLM 组餐反解失败率高 | Resolver 报错聚类 → 反馈 prompt 模板迭代；失败=拒，不降级 |
| 扩写话术与锚点语义偏差 | Review harness 蕴含检查 + 人审异常 |
| catalog-v1 重建波及旧测试 | 旧 catalog 不动、v0.5 链独立；v1.0 新测试 |
